## 1. 무엇을 재검토했나

운영 중지 직전 사이클에서 세 갈래 분석을 수행했다.

1. **온톨로지 실현가능성·가치 검증** — 5개 PoC 실험 (Bedrock Haiku/Sonnet/Titan, 재현
   하네스는 `docs/research/ontology-poc/`). 결론: 개념 층 self-serve 가능, 관계 층은
   전 도메인 최약, 검색 lift는 **jargon/코드에서만**(+25%), 일반 동의어는 0.
2. **경쟁 포지셔닝** — "Foundation" 넓이 클레임은 Databricks/Snowflake/Palantir와
   이길 수 없는 비교를 자초. 실재하는 빈틈은 **거버넌스 + 포터빌리티 + 우측 사이즈**.
3. **상품화·제품-단독 생존 분석** — 서비스(컨설팅) 함정 회피가 관건. 자동 온톨로지의
   존폐 실험은 통과했으나 **수요는 미검증**.

이후 "이대로 온톨로지를 개발할 것인가(A) vs 기존 방향(B)"을 놓고 **의도적 재검토**
(반대 논거 포함)를 수행했다.

## 3. 재확정 컨셉 (v6 후보)

### 한 문장

> **DataPond는 AI 에이전트와 AI 애플리케이션을 위한 governed·portable 데이터 접근
> 계층이다 — 인용 RAG, governed SQL, PII·접근·감사·비용 거버넌스를 개방 계약
> (S3 · PostgreSQL+pgvector · LiteLLM · OIDC · Helm) 위에서 제공한다.**

### v5.0에서 무엇이 달라지나

| | v5.0 (현행) | v6 (제안) |
|---|---|---|
| 프레임 | Portable AI **Data Foundation** | 에이전트·AI 앱의 **governed 데이터 접근 계층** |
| 소비자 | AI 애플리케이션 팀 (사람이 만드는 RAG 앱) | + **AI 에이전트** (도구로서의 데이터 접근) |
| 리드 메시지 | 파운데이션 넓이 | **거버넌스 + 포터빌리티/exit** (RAG는 기본기) |
| 온톨로지 | (없음) | **수요-게이트 옵션** — governance·관계·jargon 버티컬용 |

핵심은 **반 발짝 재조준**이지 재작성이 아니다. 시장의 무게중심이 RAG → 에이전트/context
engineering(MCP 등 도구-접근 생태계)으로 이동 중이고, DataPond의 기존 자산이 그대로
에이전트의 도구 면에 맞는다:

- governed SQL (Athena/Trino) → 에이전트의 **안전한 구조화 데이터 도구**
- governed RAG + 인용 → 에이전트의 **grounding 도구**
- PII 마스킹·접근제어·감사·스펜드 귀속 → **에이전트에게 가장 절실한 거버넌스**
  (에이전트는 사람보다 더 위험하게 데이터를 만진다)

설계 원칙: **LLM-first** — 모든 데이터 도구(온톨로지 포함)는 LLM/에이전트의 소비·생산에
최적화되어야 한다. "LLM 없이도 말이 되는" 기능이 보이면 그것은 무차별 영역이라는 경고다.

### 유지되는 것 (v5.0에서 계승)

- Portable Core 아키텍처, 개방 계약, 배포 프로필, fail-closed capability 게이팅
- 거버넌스 경계·출구 전략·Open Core 원칙 — 전부 그대로 유효
- 과대주장 금지 규율 (미구현은 로드맵으로 명시)

## 4. 온톨로지의 위치

실험이 확정한 가치 지점만 취한다: **(a) 개념 수준 거버넌스 (b) 관계/다중홉 질의
(c) jargon-heavy 규제 버티컬의 개념 확장**. "더 나은 검색"으로는 팔지 않는다.

- **Phase 0(개념 확장·정규화)**: 데모-무장 검증의 재료로만 얇게 구현 (아래 §5)
- **Phase 1(엔티티 그래프)**: 디자인 파트너가 관계/개념까지 **끌어당길 때만** 착수
- **Phase 2(GraphRAG)**: ROI 수치 증명 전 보류 유지

## 5. 실행 계획 — 데모-무장 수요 검증

순수 대기("수요 검증 먼저")를 수정한 재검토의 핵심 산출.

### 5.1 Phase 0 데모 슬라이스 (2–3주 분량, 검증 도구)

| 컴포넌트 | 내용 | 근거 자산 |
|---|---|---|
| 개념 스토어 | `ontology_concepts` + `concept_terms` (Postgres, 부트스트랩 임포트) | 실험 1 하네스 |
| 검색 확장 | `/api/ai/search`·`/api/ai/rag`에 opt-in `expand_concepts` | 실험 4b (+25% jargon) |
| 개념 PII 태그 | 개념별 민감도 → 답변·소스 표시에 반영 | 기존 PII 파이프라인 확장 |
| UI | Knowledge에 "개념으로 확장" 토글 + 사용된 개념 표시 | 기존 Grounded Answer 패널 |
| 게이팅 | `ontology` capability, fail-closed | 기존 capability 체계 |

스코프 제외: 엔티티 그래프, 관계 추출, GraphRAG, 온톨로지 저작 UI (전부 게이트 뒤).

### 5.2 게이트 구조

```
데모 슬라이스 (2–3주)
  → jargon-heavy 규제 버티컬 1곳에서 디자인 파트너 1–2곳 검증
      (의료 코딩 / 법률 / 금융 컴플라이언스 중 택1)
      ├─ "거버넌스+포터빌리티면 충분" → v6로 하든 (HA·호스티드 티어·에이전트 도구면)
      ├─ "관계/개념까지 필요"      → 온톨로지 Phase 1 착수
      └─ 수요 신호 없음            → 재시작 보류, 컨셉 재재검토
```

### 5.3 성공/중단 기준

- **성공**: 페인이 *지금* 급하고, 예산·권한이 있으며, 데이터·시간을 걸고 함께 검증할
  디자인 파트너 **1곳** 확보 (지불 경로 합의 포함).
- **중단**: 3개월 내 위 조건의 파트너 0곳 → 운영 재시작 없이 컨셉 자체를 재검토.
- **안티패턴 경계**: 한 파트너의 bespoke 요구만 좇는 컨설팅화, 무기한 무료 파트너.

## 6. 재시작 연결

운영 재시작(`OPERATIONS_PAUSE.md`의 절차)은 **§5.2 게이트에서 성공 경로가 확인된 뒤**
수행한다. 데모 슬라이스 개발 자체는 로컬/최소 환경으로 가능하며 라이브 재시작을
전제하지 않는다 (데모 시연 시점에만 기동 고려).
